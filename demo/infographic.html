Release Bundles — Concepts & Building Blocks

A visual guide to artifact metadata, Release Bundle v2, lifecycle promotion, and AQL querying — built around the Maptek Geo Suite demo.

1 — Foundation
Repository
A storage location in Artifactory that holds versioned artifacts. Each repo has a type (Docker, Maven, npm…) and a scope: local (you push to it), remote (proxies external), or virtual (aggregates multiple).

maptek-docker-local local · Docker
Artifact
Any binary stored in a repository — a Docker image manifest, a JAR, a tarball. Identified by its repo path and a content hash (SHA-256).

geo-api:2026.demo.1
maptek-docker-local/geo-api/
2026.demo.1/manifest.json
Properties (Tags)
Arbitrary key=value pairs attached to any artifact. They are searchable and filterable via AQL. Properties are the foundation of metadata-driven workflows.

project.name=maptek-geo-suite build.type=release component.team=platform
2 — How Artifacts Get Into Artifactory
💻
Source Code
Developers push code to GitHub. Each commit triggers a pipeline.
›
⚙️
CI Pipeline

›
📦
Artifacts Stored
Images land in maptek-docker-local with Docker metadata.
›
🏷️
Properties Set
Pipeline runs jf rt sp to stamp each artifact with rich metadata.
›
🎁
Release Bundle
Pipeline runs jf rbc to group tagged artifacts into a signed bundle.

4 — What Is a Release Bundle v2?
Release Bundle v2
maptek-geo-suite @ 2026.demo.2
A Release Bundle is a versioned, cryptographically signed collection of artifacts. It is the unit of promotion through environments and distribution to edge nodes.
status: COMPLETED tag: QA-Passed signed: default-lifecycle-key
📦 5 artifacts included
🔏 GPG/RSA signed at creation
🏷️ Annotatable with custom tags
🔒 Immutable once finalized
Artifacts in this bundle
geo-api/2026.demo.1/manifest.json
data-processor/2026.demo.1/manifest.json
visualizer/2026.demo.1/manifest.json
report-generator/2026.demo.1/manifest.json
auth-service/2026.demo.1/manifest.json
Created via CLI
jf rbc \
  --spec=rb-spec.json \
  --signing-key="default-lifecycle-key" \
  "maptek-geo-suite" "2026.demo.2"
Tagged via Annotate
jf rba \
  --tag="QA-Passed" \
  "maptek-geo-suite" "2026.demo.2"

5 — Dual Tagging: Per-Artifact + Collective (Bundle-Level)
Per-Artifact Properties
Each artifact has its own metadata describing what it is and where it came from. Set by jf rt sp.
component.teamplatform
component.service_typesecurity
build.typerelease
git.commitbc3797...
✅ Queryable independently of any bundle
✅ Survives bundle deletion
Collective (Bundle-Level) Properties
Describe the bundle as a whole — stamped on every artifact in the bundle. Set by jf rt sp using rb.* prefix.
rb.projectmaptek-geo-suite
rb.build_typerelease
rb.pipelinegithub-actions
✅ Cross-filterable with per-artifact props
✅ Answers "which artifacts are part of THIS release?"
Cross-Filter AQL — "Platform team artifacts from GitHub Actions release bundles"
items.find({
  "@rb.project": {"$eq": "maptek-geo-suite"},
  "@rb.pipeline": {"$eq": "github-actions"},
  "@component.team": {"$eq": "platform"}
}).include("name", "path", "created")

7 — AQL — Artifactory Query Language
AQL is a SQL-like query language for searching artifacts and their properties. Sent as a POST request to /artifactory/api/search/aql.
Script 01 — Find by project + version
items.find({
  "@project.version": {"$eq": "2026.demo.2"}
})
Script 02 — Release builds since date
items.find({
  "@build.type": {"$eq": "release"},
  "created": {"$gte": "2026-07-16..."}
})
Script 03 — Filter by team
items.find({
  "@component.team": {"$eq": "platform"}
})
Script 05 — Cross-filter
items.find({
  "@rb.pipeline": {"$eq": "github-actions"},
  "@component.team": {"$eq": "platform"}
})
Script 06 — Find bundles by tag (Lifecycle API)
GET /lifecycle/api/v2/
  release_bundle/records/
  maptek-geo-suite?tag=QA-Passed
8 — JFrog Xray — Security Scanning Built In
What Xray Does
Xray automatically scans every artifact in Artifactory for known CVEs, license compliance issues, and malware. Scans are triggered when artifacts are uploaded or when a Release Bundle is created.
🔍 Deep recursive dependency scanning
📋 SBOM generation (CycloneDX / SPDX)
🚫 Block downloads on policy violation
📊 Contextual analysis — exploit reachability
Vulnerability Severity Levels
Critical
3
High
7
Medium
12
Low
8
Results visible in the Release Bundle UI under the Security tab. Policies can block promotion if critical CVEs are found.
Summary — The Full Picture
🏷️
Tag Every Artifact
Rich metadata on each artifact makes them independently discoverable via AQL — regardless of bundles.
🎁
Bundle & Sign
Group artifacts into a signed Release Bundle — the immutable unit of delivery that travels through environments.
🔍
Query Anything
AQL lets you find builds by version, date, team, pipeline — combining per-artifact and collective metadata.
🚀
Promote Safely
Xray scans, policy gates, and lifecycle promotion ensure only safe, approved bundles reach production.
